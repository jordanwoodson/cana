# Cana 3.2.2-cana.6

Cana now checks installed apps for tracker code the way εxodus does. Opening an app's overview reads its APK files on the device and matches the classes they define against the bundled Exodus Privacy signatures; the Components tab only ever saw trackers that register a manifest component. Results are cached per app version, and nothing is uploaded.

- Filters gain a Privacy group with a "With trackers" filter, a scan of every installed app in the selected profile with progress and cancel, and tracker sorting. The More menu can start the scan too, and tiles show a tracker badge once an app has been scanned.
- The overview links to the app's public Exodus report page and names the active signature source.
- A custom bloat list may declare a `source` per package, for example when it merges several upstream lists; the overview shows it as "List source". Lists without it behave exactly as before.

Install over the existing Cana release, or update through Obtainium from this repository. Application id remains `io.github.jordanwoodson.cana`; version code advances from 229 to 230. The release uses the existing signing identity.

Validation: 173 JVM tests passed (eleven new tests cover the DEX parser, the signature matcher and the scan cache; one parses Cana's own debug APK and finds no tracker), the debug and release builds passed, and release lint reported zero errors (472 warnings, mostly untranslated strings).

Known limits: the tracker scan was not exercised on the emulator or a physical device for this release, so scan timing on very large APKs is unmeasured; a failed scan is reported per app and never blocks other features. Signature matches identify tracker code, not proof that data is collected. Everything listed for 3.2.2-cana.5 still applies.
