# Cana 3.2.2-cana.5

Batch uninstalls, disables and other package actions now run close to Canta's speed. The safety review that gates each action is queried from Android once per profile and shared across the whole batch instead of being repeated for every package, and the app list is rebuilt once when the batch finishes rather than after every item.

- Safety baselines (role holders, keyboards, device admins, protected handlers, installed set and bloat metadata) are cached per profile for 60 seconds. Every package in a batch is still checked against that baseline, failed queries are never cached, and the cache is dropped when a batch completes so the next review sees fresh role holders.
- Batches mark inventories stale while running and trigger a single full package scan at the end, so the scan no longer competes with the operations themselves.
- Each uninstall still waits for Android's PackageInstaller result before it is journaled, so History, Undo and recovery keep working exactly as before. This remains the one deliberate difference from Canta, which never waits for the result.

Install over the existing Cana release, or update through Obtainium from this repository. Application id remains `io.github.jordanwoodson.cana`; version code advances from 228 to 229. The release uses the existing signing identity.

Validation: 161 JVM tests passed (four new cache tests and one new batch callback ordering test), the debug and release builds passed, and release lint reported zero errors (444 warnings, mostly untranslated strings). The speed-up was verified by reading the code path, not by timing it on a device.

Known limits: no on-device timing was recorded for this release. Everything listed for 3.2.2-cana.4 still applies: physical/OEM devices and root-backed Shizuku were not tested, unresolved installer outcomes may require manual review, and Undo cannot recover deleted app data or missing APKs.
