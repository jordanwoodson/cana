# Canta 4.0 follow-up

Cana adopts three improvements identified while reviewing [Canta 4.0](https://github.com/samolego/Canta/releases/tag/v4.0.0): retain removed-app icon metadata, load icons off the UI thread, and keep packages visible when individual metadata reads fail. Cana's package-operation engine and profile-isolation protections remain unchanged. Work profiles use the normal debloat-list ratings and descriptions, restored in commit `4fc3ad3`.

## Behavior

- Inventory entries retain the selected profile's `ApplicationInfo`, including entries removed from Cana's own profile. Icons remain available while Android retains a readable APK.
- Coil loads, rasterizes and badges icons on a bounded IO dispatcher. Its memory-cache key includes the profile, APK identity, resource configuration, size and relevant package state. Unknown APK identity disables caching; failed loads can be retried. A changed profile or APK resets the painter immediately.
- Work badging uses a private, sized bitmap so Android cannot mutate the personal profile's icon or reject a drawable without intrinsic dimensions.
- Label or enabled-state lookup failures preserve the inventory entry, available state and debloat guidance. Missing labels fall back to the full package name. Missing application information leaves the app type unknown and visible in both scopes. Rows and details disclose incomplete metadata. Coroutine cancellation still propagates.

## Verification

On the final source, JDK 21 and Android SDK 36:

```sh
./gradlew :app:testDebugUnitTest :app:lintRelease :app:assembleDebug :app:assembleDebugAndroidTest
```

All 247 unit tests passed; release lint and both debug builds passed. Lint still reports warnings, including incomplete translation coverage.

Twelve instrumented tests passed on an isolated Android 15 emulator with personal user 0 and managed user 10. They cover real removal/restoration and APK replacement, icon cache reuse and separation, retry after a failed icon read, missing target-profile metadata, safe work badging, background icon lookup and rendering, delayed completion after a profile switch, incomplete metadata visibility, inventory-load cancellation, and equal profile ratings. Independent code review found no blocking issues.

The first regression run failed on the old code for removed-app metadata retention, broken labels, missing application information, and main-thread icon loading. The expanded profile-switch test also exposed Android's intrinsic-size requirement for badging; the final run passed after rendering a private bitmap first.

### Reproduce the device checks

Use a disposable emulator whose first managed profile is user 10; the tests install, update and remove only the code-free `io.github.jordanwoodson.cana.iconfixture` package. Build the debug APK first so the standard Android debug keystore exists. The fixture builder requires SDK platform and build-tools 36.0.0.

```sh
export ANDROID_SERIAL=emulator-5558 # select your disposable emulator
adb shell pm create-user --profileOf 0 --managed 'Cana icon work'
adb shell am start-user -w 10
fixture_dir="$(scripts/create-icon-test-fixtures.sh)"
adb push "$fixture_dir/icon-v1.apk" /data/local/tmp/cana-icon-v1.apk
adb push "$fixture_dir/icon-v2.apk" /data/local/tmp/cana-icon-v2.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -e class 'io.github.samolego.canta.ops.AppMetadataDeviceTest,io.github.samolego.canta.ops.AppIconDeviceTest,io.github.samolego.canta.ui.AppIconLoadingUiTest,io.github.samolego.canta.ui.AppListLoadingDeviceTest,io.github.samolego.canta.ui.ProfileRatingsUiTest' io.github.jordanwoodson.cana.test/androidx.test.runner.AndroidJUnitRunner
```

These checks cover Android 15 on an emulator; physical devices, OEM-specific resource behavior and every supported Android version were not exercised.
